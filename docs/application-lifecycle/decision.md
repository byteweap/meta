# 生命周期由 Run 统一收尾

## 状态与约束

2026-11-11，依据用户确认的第 4 步范围采用。用户要求代码简单清晰，不需要历史接口行为兼容。需求见 [需求记录](requirements.md)。

## 选择

使用必需的 `Server.Ready` 信号表达异步启动完成。App 的单次 `Run` 负责启动、等待就绪、注册和完整清理；`Stop` 只取消运行上下文，清理错误由 `Run` 返回。

曾考虑在 `Stop` 中同步执行清理并用锁或 once 防重入。这会使启动尚未完成时的清理与启动争用状态，也可能让钩子内调用 Stop 等待自身。由 Run 收尾可以直接覆盖所有提前返回路径，并天然保证一次清理。

曾考虑将 `Start` 改为初始化后立即返回，再增加退出结果接口。保留持续运行的 Start 并增加一个就绪通道，需要的接口和实现调整更少，仍能区分可用、失败和退出。

## 影响

自定义服务必须实现 Ready 并遵守启动与停止上下文；每个实例只运行一次。Stop 的返回不代表清理已经结束，调用方通过 Run 的返回确认完成。清理默认有 10 秒预算，所有阶段共享同一个预算，失败后仍尝试剩余清理。

若未来需要重启实例或独立等待停止，应另行明确需求和状态模型，不在本步骤加入预留兼容层。
