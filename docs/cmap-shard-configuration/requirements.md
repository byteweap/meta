# 第 16 步：并发 map 分片配置归属

## 背景与目标

原实现运行时读取可变全局 ShardCount。创建 map 后修改该值，会改变旧实例的键定位、计数范围及遍历等待数，造成查找失败、越界、挂起或数据竞争。测试及基准也通过修改全局值配置分片，不能安全共存。

用户于 2026-11-11 确认第 16 步四项方案，基线为第 15 步提交 `298b5f8`。代码简洁优先，不做历史接口兼容。本步采用 Level 2 记录，覆盖构造接口及并发配置归属变化。

## 已确认行为与设计选择

- 删除可变全局 ShardCount，提供不可变 `DefaultShardCount = 32`。统一使用 `New(hash, shardCount) (*ConcurrentMap, error)`；调用方显式传入分片数，非正数及 nil hash 返回 nil 和错误。
- 构造成功后，分片切片长度不变，是该实例唯一的分片数量来源。键定位使用其长度取模，计数直接遍历切片，快照通道和等待计数按实际分片数分配。不另存冗余分片数字段。
- 删除仅作转发的 create；保留单一显式构造入口。配置只有一个数值，不新增可选参数、Option 层或旧接口包装。仓内没有生产调用点，迁移范围为包测试、基准及 README 示例。
- 测试与基准直接创建指定分片数实例，不修改/恢复全局变量。JSON 测试使用 2 分片，现有不同分片基准保持其原负载与测量目的。
- 保留现有每分片锁及普通操作行为。Count、Keys、Iter、Items、Clear 和 JSON 在并发修改时仍不提供跨分片原子快照；hash 由调用方提供，须确定、支持并发调用，实例使用期间不可改变路由结果。零值 map、锁内回调约束及回调 panic 不在本步扩展范围。

## 验收标准

| ID | 标准 | 验证方法 |
|---|---|---|
| AC-01 | 非正分片数及 nil hash 构造失败，正分片数可用，默认常量为 32 | 构造回归 |
| AC-02 | 1/3/32/64 等不同分片实例共存，后创建实例不影响旧实例定位、计数和数据 | 多实例读写及枚举回归 |
| AC-03 | Keys/Iter/Items/Clear/JSON 使用实际分片数，不挂起或越界，实例数据互不影响 | 枚举、清理和序列化回归 |
| AC-04 | 并发构造、读写及枚举正常，静止后数据完整，无分片配置数据竞争 | 并发回归及 race |
| AC-05 | 旧测试与基准迁移完整，普通/race、基准冒烟、21 模块构建及独立审查完成 | [实施与验证](progress.md) |
