# 第 11 步：Consul 空快照

## 背景与目标

Consul 适配器仅在实例列表非空时缓存和广播，导致服务首次为空时 Watch.Next 等不到初始状态，最后一个节点下线后旧路由仍留在缓存。新增监听者也忽略已有空缓存。GetService 将成功的空结果与真实请求失败混为“服务未找到”，隐藏底层错误。

用户于 2026-11-11 确认本步骤：成功空结果正常传递，缓存区分尚未初始化和已得到空结果，保留远端真实错误，补齐回归、独立审查和记录。基线为第 10 步提交 `8570d5f`。采用 Level 2，记录缓存状态及公开查询语义变化；代码简洁优先，不做历史兼容。

## 范围与规则

- 首次远程查询成功后，无论实例数量都缓存并通知监听者；后续成功查询的索引变化时同样允许发布空结果。
- 已初始化缓存可以为空，包括自定义 resolver 返回的带类型 nil 切片。新 Watch 必须收到已有空状态，GetService 必须直接返回该缓存，不额外查询远端。
- 未初始化的缓存和不存在的缓存走远程查询；成功空结果返回 nil 错误，失败返回底层错误。
- ListServices 使用同样的初始化判断，列出已经缓存的空服务；未初始化服务不列出。
- 后台查询失败沿用现有重试和缓存保留行为，不把失败当作节点全部下线；后续成功结果仍可更新。
- 不新增状态字段、策略接口或依赖；通过 atomic.Value.Load 的类型断言结果区分未初始化与已缓存空切片，不以长度或切片是否 nil 判断初始化。

## 边界

保持当前索引通知、拉取间隔、共享监听和生命周期模型。不修改多数据中心索引聚合、初始化失败清理或并发 Stop 等其他问题，不修改其他注册中心。Watch 是最新快照通知，事件可合并，不保证逐个历史状态都被消费。

测试采用本地 HTTP 替身覆盖实际 Consul SDK 调用链；不连接真实 Consul。已有真实服务测试保留为显式 integration 测试，本地可执行部分保持默认运行。

## 验收标准

| ID | 标准 | 验证方法 |
|---|---|---|
| AC-01 | 首次无实例时 Watch.Next 正常返回空快照 | 首次空查询与有界 Next 回归 |
| AC-02 | 有节点→空→恢复时，Watch 和 GetService 反映当前状态，旧节点被清除 | 控制响应列表与索引的状态转换回归 |
| AC-03 | 新监听者收到已有空缓存，查询不回源；typed nil 与非 nil 空切片均有效 | 请求计数及自定义 resolver 回归；ListServices 包含已缓存空服务 |
| AC-04 | 未初始化时成功空结果与真实失败可区分；失败不清空有效缓存 | HTTP 错误、请求取消及后台失败恢复回归 |
| AC-05 | 本地测试、race、集成编译、21 模块构建及独立审查通过，记录同步 | [实施与验证](progress.md) |
