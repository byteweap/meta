# 单一刷新循环与独立实例生命周期

## 状态

2026-11-11，[需求](requirements.md) 已确认；实现、本地验证和独立审查完成，用户已确认提交。证据见 [实施与验证](progress.md)。

## 选择与依据

只给 map 访问加锁不能解决先通知后更新、多个刷新请求乱序覆盖以及同服务 watcher 互相替换。因此保留一条刷新循环，统一处理首次/周期/订阅触发请求，并在锁内发布整个成功快照和发送非阻塞通知。缓存读取复制可变数据，完整空缓存是有效状态；刷新失败保留上次成功结果，首次失败可返回错误。

订阅直接按 watcher 身份保存，使用容量为 1 的信号通道，无需每次广播启动回调协程。Stop 和 context 取消共用幂等清理，只删除自己的订阅，不关闭通知通道。查询与 Next 共用转换，避免两套快照语义。

客户端请求使用局部服务器顺序，避免对共享地址写入。实例生命周期以服务和实例的组合标识管理，实例操作门串行注册/注销；状态引用计数使等待者、进行中的操作和有效心跳共用同一状态，无引用且无心跳后回收。取消旧任务并等待退出后才注册或注销，等待不占用全局映射锁；旧任务退出仅清理自身身份匹配的记录。发现缓存只用于查询，不作为是否需要重新注册的依据。

实例操作门获取后再次检查调用 context，避免预取消调用因同时获得可用门而停止已有心跳。刷新和心跳使用生命周期 context，注册同时受 Registry 生命周期约束；显式注销使用调用方提供的清理 context，以保留 [应用生命周期](../application-lifecycle/requirements.md) 中停机后仍完成注销的约定。

## 影响与回退

调整错误返回和内部订阅/心跳接口，不做历史签名兼容。通知可合并，已有成功缓存的调用方在网络失败期间继续获得旧结果；未引入缓存过期策略。HTTP 请求已有 context 和 3 秒默认超时，不需要新增后台代理来模拟取消。操作失败后不自动恢复已经停止的旧心跳，由调用方根据错误决定重试注册或注销。

如果回退，必须整体回退缓存/通知和客户端实例生命周期行为，不能恢复共享 map 无锁读、按服务覆盖实例任务或持锁阻塞取消。远端系统对已收到请求的处理不具备本地事务保证，本步骤不承诺跨进程注册互斥。
