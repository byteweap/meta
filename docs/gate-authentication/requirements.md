# 网关握手前身份验证

## 背景与目标

本变更是项目审查修复计划的第 3 步。[第 2 步](../release-script-portability/progress.md) 已提交为 `3c23403`。

网关当前默认信任请求参数 `uid`，并在 WebSocket 连接建立后才检查用户 ID。目标是要求业务显式提供身份验证，在建立连接前拒绝无效身份，确保后续会话使用同一次验证得到的用户 ID。

本步骤涉及身份验证边界，采用 Level 2 追溯。用户要求代码简单清晰，不需要历史版本兼容。

## 已确认范围与实现选择

用户于 2026-11-11 确认第 3 步的显式身份验证和握手前检查方案。

- 复用 `UserIDExtractor` 和 `IDExtractor func(*http.Request) int64`，业务负责验证凭据，返回正数表示认证用户 ID，返回非正数表示认证失败。
- 删除默认读取请求 `uid` 的实现；未配置验证函数时，启动校验返回明确错误。
- 请求路径匹配后，在 WebSocket 升级前调用验证函数一次。无效身份返回 HTTP 401；错误路径保持 HTTP 404。
- 通过 Melody 的会话初始 keys 传递验证结果，连接回调直接使用该用户 ID。
- 同步 README、网关示例及针对性回归测试。示例使用环境变量配置的 Bearer 凭据映射到固定演示用户，实际业务应接入自己的凭据验证服务。

实现继续使用现有回调与 Melody 接口，不引入认证框架、额外依赖或兼容分支。会话抢占、资源清理、服务发现和 panic 恢复分别属于后续步骤。

## 验收标准

| 编号 | 标准 | 验证方式 |
|---|---|---|
| AC-01 | 未提供验证函数或显式提供 nil 时拒绝启动；有效配置可通过校验 | 配置和启动校验测试 |
| AC-02 | 非正数用户 ID 在升级前得到 HTTP 401，伪造查询参数不能绕过验证；无会话注册、定位绑定或事件广播 | 真实 WebSocket 握手与组件替身 |
| AC-03 | 成功握手的会话和定位器使用验证函数返回的用户 ID，每个请求仅验证一次 | 返回 ID 与请求参数不同的握手测试 |
| AC-04 | 不匹配的路径返回 HTTP 404，且不执行身份验证 | HTTP 请求测试 |
| AC-05 | README 和可构建示例展示显式凭据验证，不提供请求 uid 回退 | 示例检查及全模块构建 |
| AC-06 | 现有网关测试通过，目标认证测试无数据竞争 | 网关测试及目标 race 检查 |

## 验证边界与剩余责任

框架提供验证入口和执行顺序，凭据校验的正确性由业务提供的函数负责。本步骤使用本地 HTTP/WebSocket 和组件替身测试，不连接真实 Nacos、Redis 或 NATS，也不接入真实身份服务。
