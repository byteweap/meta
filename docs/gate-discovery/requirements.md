# 第 8 步：发现初始化与恢复

## 背景与目标

原 Gate.ensure 在监听创建后立即返回空选择器，首条路由可能在首次通知前选点失败。监听的 Next 出错后协程退出但缓存保留，后续请求永久使用不再更新的节点。

用户于 2026-11-11 确认本步骤：先加载当前快照，失败释放资源，监听失败后按需重建，并验证并发和停止边界。代码简单清晰优先，无历史版本兼容要求。采用 Level 2，涉及发现任务的并发与资源归属；选择见 [决策记录](decision.md)。

## 范围与规则

- 首次发现先建立 Watch，再同步调用 GetService；用当前快照初始化选择器后，才发布缓存并返回调用方，不等待首次 Next。
- 空快照是有效初始化结果，选择器返回无可用节点；后续通知可更新为可路由状态。
- 同服务并发初始化通过既有 singleflight 共用一次 Watch、GetService 和选择器初始化。
- Watch 或 GetService 失败时不保留半成品。Watch 同时返回非空监听器和错误时，也要关闭该监听器。
- Next 失败或任务取消后使旧选择器失效，按缓存项身份移除对应项；后续请求按需重建，不由后台循环无限重试。
- 每个监听器仅关闭一次。停止期间不发布迟到缓存，取消与关闭在缓存锁外执行；Stop 等待初始化、监听及其关闭真实完成，并保留关闭错误。

## 范围边界

本步骤只修改 Gate 的发现流程及测试，不变更 Registry/Watcher 公共接口。各注册中心自身的首播、空快照和通知问题仍在后续对应步骤处理。

GetService 与 Watch 没有共同的版本衔接协议，因此这里保证首个选择器完成快照初始化及失效后的按需恢复，不承诺跨调用无缝强一致，也不屏蔽适配器自身返回旧快照的问题。忽略 context 或阻塞在无 context 关闭方法的组件不能被强制终止；调用方超时不代表清理已经完成。

## 验收标准

| ID | 标准 | 验证方式 |
|---|---|---|
| AC-01 | 首次请求等待同步快照，取得节点后即能路由，不依赖首次 Next | 控制 GetService/Next 时序的 dispatch 测试 |
| AC-02 | 初始空列表正常返回，后续监听更新可恢复路由 | 空快照及后续更新测试 |
| AC-03 | 初始化错误关闭所有已取得资源且不缓存，下一请求可重试 | Watch/GetService 失败路径测试 |
| AC-04 | 并发初始化只执行一次并返回同一已初始化选择器 | 并发屏障测试 |
| AC-05 | 监听失败清空旧节点，旧关闭阻塞不妨碍新请求重建；旧任务不删除新缓存 | 受控 Next/Stop 竞态测试 |
| AC-06 | 与停止竞争时不缓存迟到资源，每个监听器仅关闭一次，Stop 等待并汇总错误 | 初始化和监听关闭与 Stop 竞态回归 |
| AC-07 | 相关回归、Gate race、21 模块构建及独立审查通过，记录有效 | [实施与验证](progress.md) |
