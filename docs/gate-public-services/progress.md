# Gate 服务可用性验证

[验收范围](requirements.md)和 [Gate 转发流程](../../README.md)描述新增服务的发现条件和失败回包。

## 设计决定

服务就绪并注册后默认可访问。Gate 的唯一服务清单来自注册中心。此前评估过 Gate 静态名单和 Mesh 路由能力标记，两者都要求额外声明；当前实现直接采用注册实例，业务命令由 Mesh 分发。服务注册契约无须扩展。

首次请求先按名查询，有实例才建立监听，随后再取一次快照以覆盖订阅建立期间的变化。监听和第一次查询分属不同接口，两次查询只发生在建立缓存时。同一服务的并发请求共用初始化。Gate 遇到空快照或监听错误时释放缓存和监听，下次请求可立即重新发现。

已绑定玩家按本地快照中的实例 ID 校验；实例消失后改投其他节点会绕过业务的状态归属，因此 Gate 在原连接回复失败。若服务没有任何匹配实例，返回 404；若服务仍可用但玩家绑定已失效，返回 503。注册中心查询本身报错时也返回 503。

## 验收证据

| 行为 | 验证 |
| --- | --- |
| 未上线、上线、实例替换、全部下线和重新上线 | [动态发现回归](../../server/gate/gate_discovery_initial_test.go)只给注册实例提供名称和 ID，在一个 Gate 中依次更新快照，检查发布目标、绑定失效、监听回收和缓存命中时的查询次数 |
| 首次查询与订阅之间服务消失 | 同文件的 `TestGateServiceDisappearsWhileSubscribing` 验证 Gate 关闭刚创建的监听，清除未完成的发现结果 |
| 原连接接收错误响应 | [WebSocket 回归](../../server/gate/gate_dispatch_test.go)覆盖查询、定位、监听与发布错误，并验证重连后复用 seq 的隔离 |
| 成功转发复用原帧 | [原帧测试](../../server/gate/gate_envelope_test.go)检查 Broker 收到的切片地址及会话 ID |
| Mesh 处理未知业务命令 | [Mesh 路由回归](../../server/mesh/handle_test.go)验证 Mesh 返回 404 |

## 本地验证

根模块测试、Gate 竞态测试和全部 21 个模块的 `make check` 构建通过。按约定跳过了同进程中启动多个节点的两项既有用例。Gate 示例模块编译及 lint 通过。外层协议已重新生成，Go 绑定只更新了注释。

根模块增量 lint 为零。全量 lint 默认显示 13 项。关闭相同诊断数量上限后，当前工作区和基线 `5952969` 各有 14 项，文件、行号和诊断文本逐项一致。

[成功转发基准](../../server/gate/gate_dispatch_bench_test.go)使用 128 字节业务载荷，玩家已绑定且发现缓存已预热。测量从处理预编码帧到内存 Broker 接收原帧，不含网络 I/O。Apple M1、Go 1.27.1、单核五轮的中位数为 800.8 ns/op，范围为 787.4–819.9 ns/op。基线中位数为 791.2 ns/op，两版均为 1020 B/op、21 allocs/op。
