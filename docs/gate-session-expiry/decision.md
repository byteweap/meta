# 每次 Gate 运行使用一份租约

Gate 进程异常退出会影响该次运行接纳的全部连接。每次启动生成一个全新的运行 ID，建立一条带 Redis 原生 TTL 的键。Gate 只延长已有的租约。存储拒绝续期，或最后一次确认的期限耗尽时，Gate 停止该次运行。Gate 以成功请求开始时间加 TTL 计算本地期限，避免把请求往返时间误算成额外有效期。后续启动会生成新的运行 ID，复用相同应用 ID 不会恢复旧会话。

会话查询先读用户归属，再检查对应的租约。连接认领先记录已有会话 ID，检查租约后比较 ID 并原子更新单个用户 Hash。认领遇到并发覆盖时，从读取和租约检查重新开始。两个键可以处于不同 Redis Cluster 槽位，因此各用单键命令。读取时可能遇到并发重连，结果按取得的归属快照判断。普通业务位置继续用 `HGET` 和 `HGETALL`。正常释放依旧原子校验节点与会话 ID。

已确认从逐连接续期改成逐 Gate 续期。Redis 的周期更新数随 Gate 数量增长。代价是在线会话查询多一次读，以及该 Gate 仍运行时，单个断开未能释放的位置仍可能保留。注册中心可以提供实例存活信息，采用它需要为各适配器分别约定实例摘除时限。使用 Redis 原生 TTL 可直接给会话定位提供统一的失效窗口。[Redis SET](https://redis.io/docs/latest/commands/set/) · [Redis PEXPIRE](https://redis.io/docs/latest/commands/pexpire/)
