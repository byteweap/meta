# Mesh 客户端请求处理

本次在既有 Gate → Broker → Mesh 消息链路上引入类型化返回值，沿用现有 envelope 和 Broker 回包元数据。公共 Go API 与错误行为按 Level 2 记录。

- Mesh 在注册时拒绝重复的客户端命令与版本，原处理器仍可使用。
- 类型化 handler 接收标准 context、已认证用户身份和 Protobuf 请求，返回 Protobuf 响应或错误。空请求体沿用 nil 语义。
- 能识别请求及回复地址时，未知路由、无效业务载荷和类型化 handler 失败应得到明确响应。成功与失败均回填原请求的关联号和会话身份。
- 客户端路由统一通过 `Route` 注册，移除 `RouteX`。手动回包和单向消息通过 `Wrap` 适配原 handler，服务间 RPC 保留既有调用方式。性能以相同输入的 Mesh 消息处理基准记录。
- game 示例的进入和退出命令均需确认。退出成功时回复原请求，成功响应可省略业务消息体。
