# Mesh 停服排空实施记录

基线为 `66d7780`。按 Level 2 记录生命周期契约。[验收范围](requirements.md) · [实现决策](decision.md)

- [App 清理](../../app.go)在停止前钩子和注销前调用支持排空的服务。启动阶段仍由应用的取消信号中断。已就绪后的执行沿用现有 `StopTimeout` 预算。
- [Mesh 停止](../../server/mesh/drain.go)关闭准入并在预算内继续执行与回包。RPC worker 仍受原并发上限约束。绝对期限在开始新工作或回包前同步检查，防止超时回调调度延迟时继续发送。
- [排空回归](../../server/mesh/drain_test.go)覆盖 App 发起停止、先关闭准入、串行和并发队列执行、队列中超时返回 504、客户端回包顺序、嵌套 RPC、满队列唤醒和回包阶段取消。[启动取消回归](../../app_test.go)验证应用停止仍可中断未就绪的服务。
- 单个 Mesh 连接实际 NATS，两个 RPC 已入队后触发 App 停止，两次调用均收到 200 及原载荷。专项验证通过三轮竞态检查。
- 根模块按约定跳过两项单进程多节点用例。App 和 Mesh 通过五轮竞态检查，排空相关专项通过二十五轮竞态检查。NATS 模块竞态检查、game 示例测试、相关包 lint 和 `make check` 的 21 个模块构建通过。

## 排空边界

Mesh 排空已成功入队的消息。NATS 缓冲中尚未进入本地队列的消息由订阅取消处理。生命周期依赖 handler、Broker 和钩子遵守上下文。Gate 的连接关闭以及跨进程客户端确认继续遵循各自的传输约定。

## 本地性能

Apple M1、Go 1.27.1，使用 `BenchmarkRPCReceive` 发送带 128 字节业务数据的 Protobuf 请求。单核、单个在途请求，内存 Broker 测量从订阅回调到收到回包，五轮各 400 毫秒。

| 配置 | 基线中位数 | 本次中位数 | 两版每次分配 |
| --- | ---: | ---: | ---: |
| 默认串行 | 749.3 ns/op | 672.6 ns/op | 384 B，8 次 |
| 两个 worker | 746.4 ns/op | 744.5 ns/op | 784 B，10 次 |

该数据仅覆盖本地收发路径。[基准代码](../../server/mesh/rpc_deadline_bench_test.go)
