# Mesh 停服排空

以 `66d7780` 为基线。停止时先关闭 Mesh 的消息准入，再在清理期限内执行并回包已入队的 RPC、客户端消息和会话事件。按 Level 2 记录生命周期契约和验证。

- `App.Run` 开始清理时，先通知支持排空的服务停止接收，再执行停止钩子和注销。应用就绪前的取消仍能中断启动。排空使用现有 `StopTimeout` 预算。
- `Mesh.Stop(ctx)` 也可单独发起排空。首次停止决定排空期限，直接调用没有截止时间时使用 10 秒。后续调用可继续等待清理。
- 消息在成功进入 Mesh 队列时视为接纳。排空保留串行处理顺序和 RPC worker 上限。已接纳请求仍可调用下游，原有 RPC 截止时间仍有效。
- 排空期限耗尽时取消执行和回包，后续出队的消息跳过业务。实现需要 handler 和 Broker 响应上下文取消。直接取消独立启动的 Mesh 仍走原停止路径。
- 验证覆盖串行和并发队列、接收关闭、下游调用、超时和重复停止。沿用单个服务的验证方式。
