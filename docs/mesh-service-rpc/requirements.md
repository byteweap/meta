# Mesh 按服务名发送 RPC

基于 `880b9d4`，新增 `RequestService(ctx, service, cmd, version, data)`。调用方提供逻辑服务名，Mesh 用当前应用名和一个可用实例构造 Broker subject，沿用已有 RPC 截止时间与回包约定。

- 首次发现合并同名并发请求，等待者可独立取消。快照命中时只在本地选点，服务上下线与监听异常按现有 Gate 发现规则处理。
- 调用方过期、Mesh 停止和没有可用实例均能结束等待。一次调用最多向 Broker 发送一次，传输失败原样返回。
- 用受控注册中心与 Broker 验证寻址、取消、并发初始化、下线更新和释放监听，并测量缓存命中的开销。
- 最后一个等待者取消尚未发布的初始化时，后续请求可以重新发现。迟到的旧结果不能覆盖或移除新快照。后台组件异常应释放已获得的监听，监听器的关闭错误由 Mesh 停止时返回。
- Mesh 订阅中的发送方通配符由框架生成。配置中的通配符在启动时拒绝，首次快照没有合法投递地址时直接返回无可用实例。
