# Go 版本一致性与全模块构建检查

## 背景与目标

本变更是项目审查修复计划的第 1 步，共 16 步。主模块升级到 Go 1.27.1 后，依赖主模块的独立子模块需要声明兼容的最低 Go 版本。根目录的 `go test ./...` 仅覆盖主模块，需要一个覆盖各独立模块的构建入口。

采用 Level 2 追溯，原因是本步骤涉及跨模块版本声明和构建流程。

## 已确认范围

用户于 2026-11-11 确认以下内容。

- 将工作区已有的 19 个 `go.mod` 改动纳入本步骤，包括主模块、18 个依赖它的子模块，以及主模块中 Gorilla WebSocket 的直接依赖声明。
- 在 [Makefile](../../Makefile) 中增加 `make check`，动态发现全部 Go 模块，并逐一执行只读依赖构建。实际命令采用 `go build -mod=readonly -o /dev/null ./...`，避免单个 main 包的默认输出名与源码目录冲突。
- 构建遇到失败立即退出，输出应能定位失败模块。
- 更新 Makefile 的帮助信息和 [README 开发命令](../../README.md#开发命令)。
- 本步骤完成并验证后，由用户决定是否提交，然后确认第 2 步方案。

设计以代码简洁、清晰为优先，整个修复计划无需历史版本兼容。当前 CLI 和 gate-client 未依赖主模块，其最低 Go 版本按各自模块需求声明。

## 实现约束

- 复用现有 Makefile 和模块发现方式，构建入口直接遍历 `go.mod`，排除 `.git` 下的文件。
- 构建使用只读依赖模式，验证中核对 `go.mod` 与 `go.sum` 的内容摘要。
- 每一步实施前确认方案，实施和验证完成后询问是否提交。
- 后续步骤的接口、数据格式和行为调整分别在对应步骤确认。

## 验收标准

| 编号 | 标准 | 验证方式 |
|---|---|---|
| AC-01 | 主模块及 18 个依赖它的子模块声明 Go 1.27.1，Gorilla WebSocket 作为直接依赖与代码引用一致 | 检查模块声明、依赖和现有差异 |
| AC-02 | `make check` 覆盖当前全部 21 个模块并成功构建 | 执行 `make check`，核对输出中的模块集合 |
| AC-03 | 任一模块构建失败时立即停止，并能定位失败模块 | 在临时目录中使用模拟 Go 命令验证目标执行行为 |
| AC-04 | 构建检查不改写依赖声明和校验文件 | 比较检查前后所有 `go.mod`、`go.sum` 的内容摘要 |
| AC-05 | 帮助信息、README 与实际入口一致，追溯文档链接有效 | 执行 `make help`，检查文档和本地链接 |
