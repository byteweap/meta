# 第 10 步：Nacos 服务身份转换

## 背景与目标

注册仅在 Metadata 非 nil 时保存应用 ID；查询和监听却读取 Nacos 自身的 InstanceId，服务名也可能带分组修饰，无法与应用实际订阅的路由对应。查询还直接改写 SDK 元数据，元数据为空时可能 panic。首次查询与监听更新使用不同筛选路径，集群、健康状态和权重结果不一致。

用户于 2026-11-11 确认：注册始终保存应用 ID，查询和监听共用转换，统一集群、健康与空列表行为，缺少应用 ID 的实例跳过并记录，不回退到 Nacos ID。采用 Level 2，涉及注册数据和发现结果语义；无历史兼容要求。

## 范围与规则

- 注册的应用 ID 和服务名必须非空。每个 endpoint 的元数据先复制，再写入 id、version、kind；不修改调用方的 map。
- GetService 与 Watch.Next 使用同一个查询和转换入口。请求携带相同配置的 Group、Cluster；结果只含健康、启用且权重为正有限值的实例。
- ServiceInstance.ID 使用 Metadata[id]，Name 使用请求的原始服务名。SDK 的 InstanceId 和带分组的 ServiceName 不参与框架路由身份。
- 缺失或空应用 ID 的实例跳过并记录日志；无兼容回退。返回 Metadata 独立于 SDK 缓存和其他返回结果，不允许别名写入污染。
- Version、协议和向上取整的权重在查询与监听中保持一致；协议缺失或为空时使用配置的默认协议。
- 空实例列表或过滤后为空时返回正常空快照，不作为发现故障。SDK 查询错误仍返回调用方。
- 客户端初始化需设置 `UpdateCacheWhenEmpty: true`，允许 SDK 缓存和通知反映最后一个节点下线。适配器接收外部客户端，无法通过接口修改该选项；仓库示例与集成配置一并启用。

## 边界

不升级 SDK，不修改其他注册中心、通用路由 ID 规则或事件可靠性。SDK v1.1.6 查询方法不接受 context，取消只能在调用前后检查，不能强制中断进行中的 SDK 调用。真实 Nacos 集成依赖单独环境；本步骤使用可控客户端进行本地回归，并保留显式启用的集成测试。

## 验收标准

| ID | 标准 | 验证方法 |
|---|---|---|
| AC-01 | nil、空及已有 Metadata 的注册均保存应用 ID；空 ID 拒绝；调用方 map 不变 | 捕获 RegisterInstance 参数 |
| AC-02 | 注册后查询/监听返回原应用 ID 和服务名，不采用 SDK 修饰身份 | SDK 返回不同身份的往返测试 |
| AC-03 | 查询与监听的分组、集群、健康/启用/权重、协议和版本一致 | 公共入口回归 |
| AC-04 | 空快照正常返回；缺 ID 跳过且不 panic；错误传播 | 空列表、无效实例及失败测试 |
| AC-05 | 返回结果独立于 SDK map 和其他结果 | 修改结果后的隔离断言及 race |
| AC-06 | 单元测试、race、集成测试编译和 21 模块构建通过；独立审查与记录完成 | [实施与验证](progress.md) |
