# 使用 SDK 托管心跳并保留业务身份

## 状态

2026-11-11，[需求](requirements.md) 已确认；实现、本地验证和独立审查完成，用户已确认提交。证据与边界见 [进度](progress.md)。

## 选择与依据

应用 ID 用于消息路由，不能用服务端生成的实例 ID 替换。使用独立元数据保存业务 ID、协议和版本，保持原服务名；SDK ID 仅用于监听缓存的内部定位。注销直接使用 SDK 支持的命名空间、服务名、主机和端口，避免解析任意 ID 文本或新增本地注册表。

使用 SDK RegisterInstance 托管心跳，禁用时调用 Register；删除无停止机制的自写 ticker。相比再实现一套心跳状态机，这一方案更简单，代价是遵循 SDK 的服务端版本及在途请求限制。未设置的可选参数传 nil，让 SDK 负责默认值；每个请求独立复制指针值，避免共享可变请求。

所有地址及请求预校验避免可预见的部分成功；实际网络失败时，只清理响应确认本次新建的实例。Existed=true 的实例不删除，清理失败与原错一起返回。多 endpoint 注册不是远端原子事务，SDK 超时可能发生在服务器已处理请求之后。

## 影响与回退

不兼容旧服务名拼接及 SDK ID 格式。SDK 的地址键不含协议，因此拒绝同一 host/port 的多协议注册。SDK 只取消心跳任务而不等待在途调用结束；若将来需要更强注销顺序，需另行评估 SDK 能力或生命周期实现，不能宣称本次已提供。

保留现有 WatchService 增量订阅，仅将缓存身份固定为 SDK ID。该 SDK 通道同服务共享、不支持取消订阅且满队列可能丢事件；替代 WatchAllInstances 涉及回调顺序和初始化失败清理，不能作为无代价替换。本步不扩展订阅架构，将这些既有限制明确记录。

回退须整体回退身份、注册与监听转换，不能混用两种身份格式；远端已注册实例需要由部署方按完整地址清理。本步不更改 SDK 版本，不新增依赖。
