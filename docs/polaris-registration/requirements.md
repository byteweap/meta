# 第 14 步：Polaris 注册与实例身份

## 背景与目标

原实现默认传入零 TTL，被 SDK 拒绝；注册将协议拼到服务名并将业务 ID 改写为 SDK ID 串，注销依赖拆分该串；自行启动的心跳没有停止路径。查询和监听使用 SDK ID，与应用路由的业务 ID 不一致。

用户于 2026-11-11 确认第 14 步四项方案。基线为第 13 步提交 `582e726`。代码简洁优先，不做历史格式兼容。本步采用 Level 2 + 决策记录，覆盖注册身份、失败处理及心跳生命周期变化。

## 范围与规则

- 保留输入的业务 ID、原服务名和元数据。每个 endpoint 的注册请求有独立参数及元数据，保留 `id/kind/version` 为适配器字段。查询和监听共享转换，对外返回业务 ID；忽略缺少业务 ID/协议或不可路由的实例（不健康、隔离、权重不为正），不回退旧 SDK ID。
- 默认权重 100。TTL、超时、重试次数未设置时传 nil；显式零重试必须保留。启用心跳调用 SDK RegisterInstance，SDK 默认 TTL 为 5 秒；禁用心跳使用 Register 且不设置 TTL。删除本地心跳循环。
- 注册前解析全部 endpoint 并验证全部 SDK 请求。地址必须为 scheme://host:port，端口 1–65535，不接受凭据、路径、查询或片段。拒绝同一 host/port 的重复地址，即使协议不同。ID、服务名和地址列表不得为空。显式超时必须为正，重试次数不得为负。
- 中途注册失败或调用取消时，尽力注销之前明确新建（Existed=false）的实例；不删除预存实例。汇总原错误及清理错误。不把失败请求视作已确认新建，不承诺远端事务。
- 注销按 namespace/service/host/port 定位，不依赖业务 ID 或 SDK ID。全部地址先验证；单项失败仍尝试其余地址并汇总错误。已取消操作在调用 SDK 前返回；进行中的 SDK 请求不能由 context 强制中断。
- Watch 内部按 SDK ID 保存增删更新，避免同一业务实例的多 endpoint 相互覆盖。首次空列表有效，返回数据与内部状态隔离，Stop/取消解除等待；创建失败返回真正的 nil watcher。

## 边界与确认

SDK polaris-go v1.6.1 托管心跳要求 Polaris Server ≥1.10。Deregister 按地址键取消 SDK 任务，但 SDK 不等待正在执行的心跳/重注册退出；请求 API 不接受 context。不包装额外后台协程来模拟强制取消，也不承诺跨进程注册互斥。预存实例不会因部分失败被注销，其已有或本次建立的 SDK 心跳状态仍由 SDK 管理。真实 Polaris 服务未提供，使用无外部服务依赖的替身验证适配器行为。

现有 SDK WatchService 为同服务提供共享增量通道，初始查询与订阅有间隙，没有取消订阅接口，队列满时会丢弃事件；Stop 只取消本地等待，不关闭共享通道。本步只修复内部身份定位及输出转换，不承诺同服务多订阅广播或增量丢失恢复，不切换订阅 API。
