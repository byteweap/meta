# 发布脚本版本更新修复

## 背景与目标

本变更是项目审查修复计划的第 2 步。[第 1 步](../module-version-consistency/progress.md) 已提交为 `ee06aff`。

[release.sh](../../release.sh) 使用 awk 更新主模块的依赖版本。macOS 系统 awk 将 `\S` 作为普通字符处理，导致版本匹配失败，后续依赖校验中止发布。

采用 Level 2 追溯，原因是本变更涉及发布关键流程。实现以简单、清晰为先，使用 POSIX 字符类表达非空白字符。

## 已确认范围

用户于 2026-11-11 确认执行第 2 步。

- 将 `release.sh` 中四处 `\S+` 替换为 `[^[:space:]]+`，覆盖单行依赖、括号依赖的匹配条件和替换表达式。
- 使用临时样例和模拟 Git 命令验证版本更新及发布脚本流程。
- 本步骤实施和验证完成后，向用户询问是否提交。

## 验收标准

| 编号 | 标准 | 验证方式 |
|---|---|---|
| AC-01 | 脚本通过 Bash 语法检查 | `bash -n release.sh` |
| AC-02 | 单行和括号内的主模块依赖更新为目标版本，支持空格和制表符 | 系统 awk 下运行临时发布样例并核对文件内容 |
| AC-03 | 更新后注释、其他依赖和无主模块依赖的文件内容正确 | 对样例文件进行完整内容比较 |
| AC-04 | 带 `v` 和不带 `v` 的版本参数得到相同版本结果，重复更新文件内容幂等 | 分别运行两种参数并比较内容摘要 |
| AC-05 | 更新通过校验后，模拟 Git 收到预期提交、分支推送、模块标签和标签推送命令 | 检查模拟 Git 调用日志 |
| AC-06 | 修复能覆盖原有缺陷 | 相同样例在基线脚本中因版本未更新而失败，在修复后的脚本中通过 |

## 验证边界

测试在临时目录中运行发布脚本副本，Git 命令由模拟程序记录。验收覆盖本机 Bash 和系统 awk 下的依赖更新及脚本控制流程。真实远端发布需要在实际发布时验证。
