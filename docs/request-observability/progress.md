# 请求链路观测实施记录

[验收范围](requirements.md) · [组件契约](../../component/observe/observe.go)

- 本地 `dev` 已包含 Gate 会话租约 `64240ce` 和 Mesh 排空 `3357442`。观测分支从合并提交 `fbe1e56` 创建。
- Gate 和 Mesh 通过各自的 Option 注入同一观测组件。框架传入固定的阶段和拒绝原因，由接入方决定指标后端和实例维度。
- Mesh 复用原有队列传递入队时间，保持原消息与请求头的所有权。计时采用进程内单调时间，串行队列的计时包含阻塞入队。
- 回包计时以 Broker 调用返回为止。客户端 handler 内同步回包时，handler 耗时和回包耗时存在重叠。
- 合并基线通过根模块测试和 Redis Locator 竞态测试。观测分支通过根模块测试、Gate 和 Mesh 三轮竞态测试、game 示例测试及 `make check` 的 21 个模块构建。根模块和竞态检查按约定跳过两个单进程多节点用例。
- [Gate 专项测试](../../server/gate/gate_dispatch_test.go)验证失败回包、选点计时与拒绝事件。[Mesh 专项测试](../../server/mesh/observation_test.go)用虚拟时钟验证队列、执行和回包耗时，覆盖会话事件过滤、业务自定义 504、排空丢弃。[并发队列测试](../../server/mesh/rpc_pool_test.go)和[串行排空测试](../../server/mesh/drain_test.go)验证队列满、过期、停服和阻塞入队。专项竞态检查通过二十轮。
- 相关包 lint 检查未发现新增问题。Gate 仍有基线的 8 项 lint 问题，涉及 `bodyclose`、`errcheck` 和 `revive`。

## 复审修复

- Gate 和 Mesh 在注入时统一包装观测器。观测回调 panic 时记录日志，保留原请求处理和回包。
- 串行 Mesh 在队列观测后重新检查排空期限。启动取消、订阅失败或排空结束时，串行队列中尚未执行的请求按 `Stopping` 计数。
- [回归测试](../../server/mesh/observation_test.go)覆盖观测 panic 后的 200 和 504 回包、到期后跳过客户端 handler、启动取消和订阅失败的计数。专项竞态测试通过二十轮，三个原始复现通过五轮，Gate 和 Mesh 竞态测试通过三轮。根模块测试、21 个模块构建及变更范围 lint 复验通过。

## 默认关闭时的性能

Apple M1、Go 1.27.1。合并基线和复审修复后的观测分支交替运行五轮，每轮单核 400 毫秒，以下为中位数。Gate 测量 128 字节载荷的已绑实例帧转发，Mesh 客户端项测量 handler 分发及内存 Broker 回包，RPC 项测量 128 字节载荷、单请求在途时从订阅回调到内存 Broker 回包。

| 路径 | 基线 ns/op | 本次 ns/op | 两版每次分配 |
| --- | ---: | ---: | ---: |
| Gate 已绑定会话转发 | 757.1 | 767.0 | 996 B，20 次 |
| Mesh 客户端手动回包 | 1106.0 | 1101.0 | 1516 B，21 次 |
| Mesh 客户端类型化回包 | 1104.0 | 1094.0 | 1516 B，21 次 |
| Mesh 串行 RPC | 655.4 | 653.3 | 384 B，8 次 |
| Mesh 两个 worker 的 RPC | 690.3 | 708.7 | 784 B，10 次 |

关闭观测时跳过观测读钟和回调。Mesh 队列槽保留入队时间字段。上述基准仅覆盖本地处理路径。
