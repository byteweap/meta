# 第 15 步：座位空间边界与注册行为

## 背景与目标

原实现仅分配切片容量、长度仍为零，首次正常注册会越界；直接补足长度后，查询又将空槽视作存在，导致首次注册失败。负下标和 nil 座位同样会触发 panic。

用户于 2026-11-11 确认第 15 步四项方案，基线为第 14 步提交 `3c4d3d6`。保持代码简单清晰，不做历史接口兼容。本步采用 Level 2 记录，因为构造函数返回契约及非法输入行为发生变化。

## 已确认行为与范围

- `NewSpace(size int) (*Space, error)` 创建固定容量空间；负容量返回 nil 和错误，零容量合法。仓内没有此构造函数的调用点，无需其他模块迁移。
- 座位 ID 有效范围为 `[0, size)`。`GetSeat` 对非法 ID 或空槽返回 `(nil, false)`，只有已注册座位返回 `(seat, true)`。
- `Register` 拒绝 nil 座位、越界 ID 及重复占位，失败不改变已有座位；成功后可按 ID 查询到同一座位。
- `Unregister` 对非法 ID 或空槽直接返回；重复注销无副作用，注销后允许同一 ID 重新注册。
- 保留普通切片和直接边界判断；不增加锁、扩容策略、任意容量上限或 nil 接收者兼容。空间仍由调用方串行使用；race 检查不代表新增并发安全保证。

构造函数返回错误让非法容量可由调用方处理，与注册返回错误的风格一致。无现存调用点且不要求兼容，因此无需双构造入口或兼容包装。
