# 第 12 步：ServiceComb 完整快照监听

## 背景与目标

原 Watcher 将单条实例事件当作完整列表返回，无法保留同服务其他节点，删除事件也返回被删除的节点。它丢弃首次查询结果和订阅错误，忽略 context，直接关闭仍可能被回调写入的 channel，重复 Stop 还会 panic。SDK v0.7.0 对同一消费者只保留第一个回调，并在连接关闭后重新连接，无法通过现有接口可靠单独停止监听。

用户于 2026-11-11 确认第 12 步：改为 Next 驱动的完整查询，首次立即返回，后续间隔 1 秒；查询/监听共用并串行访问 SDK；Stop 可重复、取消等待并停止后续请求；删除测试专用 Put，补齐测试与追溯。基线为第 11 步提交 `9cb7be2`。采用 Level 2 和 [设计决策](decision.md)，涉及监听及并发模型变化；不做历史兼容。

## 范围与规则

- Watch 仅建立本地监听状态；首次 Next 立即查询并返回完整列表，含正常空列表。后续 Next 在上一次查询结束至少 1 秒后再次查询，不新增后台轮询协程。
- GetService 与 Watch.Next 使用同一查询/转换路径。调用 sc.WithoutRevision() 获取完整数据，避免未变化响应被当作查询错误。
- SDK 明确的服务不存在错误转为正常空列表；其他查询错误返回调用方。监听不把错误伪装为空，也不在内部无限重试。
- 返回 ID 为 InstanceId，Name 为请求的服务名，Version 为实例 Version；元数据和 endpoint 切片复制，避免返回值修改 SDK 数据或其他快照。忽略 nil 实例项。
- 同一 Registry 的查询串行执行，保护 SDK 共享 revision；查询排队可被 context 取消。同一 Watcher 的并发 Next 同样串行，不缩短轮询间隔。
- Stop 取消自身且允许并发重复调用，不关闭共享 SDK 客户端。取消结束轮询间隔和查询排队，阻止后续 SDK 请求；已发出的请求不能强制中断，返回后报告取消状态。
- 移除 Watcher.Put、RegistryClient 的 WatchMicroService 要求及旧回调所需的全局消费者 ID；不保留旧事件模型兼容分支。

## 边界与运行条件

变更传播需要轮询等待和请求耗时；无消费 Next 时不查询，快照可能重复，不保证逐个历史变化都被消费。默认固定间隔为 1 秒，本步骤不增加调度器、共享轮询缓存或可配置策略。

SDK 查询接口不接受单次请求 context。sc-client v0.7.0 未传递 Options.Timeout，底层 foundation/httpclient 在默认设置下使用 60 秒请求超时；不能依赖该字段缩短在途取消时间。自定义 RegistryClient 应保证查询能有限期返回。Registry 的串行保护仅覆盖自身发现查询；应让每个 Registry 独占 SDK client，不从其他 Registry 或外部并发调用同一 SDK 的发现接口。

本步骤不修改注册/注销和心跳生命周期，不升级 SDK，不修改其他注册中心。真实 ServiceComb 环境未连接，以可控客户端及真实 SDK 配本地 HTTP 服务验证，不将其视为真实服务联调。

## 验收标准

| ID | 标准 | 验证方法 |
|---|---|---|
| AC-01 | 查询和监听返回正确的完整列表、版本与独立元数据/端点 | 多节点、字段和隔离回归 |
| AC-02 | 首次为空、删除后为空及恢复均正常；已知缺服务为空，其他错误保留 | 可控响应状态序列及错误回归 |
| AC-03 | 首次查询立即执行，后续间隔至少 1 秒；无 Next 时不轮询 | 时钟/请求计数回归 |
| AC-04 | 父 context、间隔等待、排队和在途返回后的取消有效；Stop 并发重复安全 | 有界取消、并发及 race 回归 |
| AC-05 | 多服务监听独立，同 Registry 查询串行，SDK revision 不导致未变化错误 | 并发客户端回归及真实 SDK 本地 HTTP 回归 |
| AC-06 | 模块全部测试、race、21 模块构建和独立审查通过，记录同步 | [实施与验证](progress.md) |
