# 第 7 步：重连与会话归属

## 背景与目标

旧实现先替换并关闭本地连接，再绑定定位器；绑定失败会连带丢失正常连接。Redis 解绑采用先查后删，且仅比较节点 ID，同节点重连和跨节点并发绑定都可能被旧断开误删。Mesh 仅凭 UID 消费状态事件，无法识别迟到的旧上线和下线。

目标是让连接切换、位置释放和状态通知明确属于某一次会话，保留简单的业务节点定位接口。用户于 2026-11-11 确认本步骤，执行后需另行确认提交。追溯级别为 Level 2，涉及并发、接口和持久化格式；选择见 [决策记录](decision.md)。

## 范围与行为

- Gate 每次连接生成不可复用的会话 ID。先原子 Claim，成功后替换本地会话并关闭旧连接；明确失败不切换旧连接。
- 同一 Gate 内同一用户的连接和断开串行处理；不同用户可独立完成操作。跨 Gate 以定位器原子 Claim 的顺序确定当前归属。
- Release 同时比较节点与会话 ID，只有当前在线会话才能释放。重复或旧连接释放返回 false；出错或未释放时不广播离线。
- 定位器保留最后会话 ID 和离线状态；状态事件携带该 ID。Mesh 仅在读取到相同 ID 和匹配在线/离线状态时执行回调，缺失身份、查询错误或过期事件均跳过。
- Redis 定位器读取主节点，不允许副本读取和延迟/随机路由造成旧状态校验通过。
- 普通业务节点的 Bind/UnBind 保持用途；同一服务不可混用普通绑定与会话绑定。Redis UnBind 的节点比较和删除也改为原子操作。
- 直接更新接口和 Redis 数据格式，不保留历史解析或回退。Gate 和 Mesh 依赖 SessionLocator。

## 边界

本步骤不实现跨网关强制踢线、所有业务消息的会话隔离、事件可靠投递、重试队列或跨 Redis 与业务回调的分布式事务。Mesh 校验反映读取时的当前状态，不能保证任意业务回调执行期间归属不再改变。Redis 操作失败可能存在服务端已执行而响应丢失的网络不确定性；不宣称外部故障下的强事务回滚。

离线标识不自动过期，避免旧消息在标识遗失或复用后被误认。这里只保留每用户每网关服务最后一条状态，不保留会话历史；后续清理策略需要结合消息保留期限另行约定。第 8 步发现初始化与恢复不在本次范围。

## 验收标准

| ID | 标准 | 验证方式 |
|---|---|---|
| AC-01 | 新绑定明确失败时旧连接仍可用，新连接关闭，不误解绑或发事件 | 真实 WebSocket 回归 |
| AC-02 | 同节点、跨节点重连后旧释放不删除新归属；重复释放无副作用 | Gate 并发测试、执行 Redis Lua 的测试 |
| AC-03 | 同用户重叠连接/断开不能因返回次序覆盖新归属，不阻塞其他用户 | 控制时序的 Gate 并发回归 |
| AC-04 | 仅成功释放时广播带身份的离线，停止清理仍等待并保留错误 | Gate 事件与停止回归 |
| AC-05 | Mesh 过滤旧上线/下线、状态不符、缺少身份和查询失败；正常回调和 panic 恢复仍有效 | Mesh 消息处理测试 |
| AC-06 | 节点查询只返回在线路由，不泄漏身份字段；普通业务定位行为有效；会话状态读取主节点 | Redis 模块测试 |
| AC-07 | 相关测试及 race、21 个模块构建通过，追溯链接和独立审查完成 | [实施与验证](progress.md) |
