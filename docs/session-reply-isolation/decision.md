# 以原连接身份约束客户端回包

## 选择

保留 `seq` 作为请求关联号，复用 Gate 分配的 `session_id` 作为连接身份。全局请求 ID 不能阻止 Gate 把回包写给错误连接；将会话身份放进客户端 envelope 也不能替代 Gate 读取真实连接身份。因此只扩展 Broker 头。

新增 `delivery` 内部标记：`response` 指定原连接，`push` 指定按 UID 找当前连接。Gate 匹配后写入同一个会话对象，不再次按 UID 选连接；不增加热路径的远端查询或下行 Protobuf 解码。没有标记不等于推送；默认只为旧发布者保留无标记投递。

## 发布和回退

1. 先部署新版 Gate 和 Mesh，保留 Gate 默认兼容模式。带会话标识的响应已经受校验；无标识回包仍可能跨连接。
2. 自定义响应和推送按 [README](../../README.md#gate-设计) 补齐标记，确认旧链路已下线、过渡中的无标识下行已处理完毕，再启用 Gate 的严格模式。之后客户端才能依赖重连后序号可以重新从 1 分配。
3. 需要回滚发布者时，先关闭严格模式；这会重新允许旧格式下行并降低隔离保证。未确认严格部署的客户端不应依赖重连后的序号复用。

严格模式只保护框架和遵循标记契约的发布者，不把 Broker 头当作鉴权边界；业务发布者仍负责正确区分响应和推送。
