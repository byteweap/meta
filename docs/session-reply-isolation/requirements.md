# 回包会话隔离与客户端请求关联

用户于 2026-11-18 确认实施。本次涉及内部消息契约、重连行为和客户端 API，采用 Level 2 追溯。复用[已有会话身份](../session-ownership/decision.md)，不修改客户端 envelope 或新增 `request_id`。

| 验收项 | 要求 |
|---|---|
| AC-01 | Gate 以实际收到帧的连接为准传递会话 ID；Mesh 的成功和失败回包回填该 ID，异步使用 `Context.Copy()` 也保留它。路由、主题和原始帧透传不变。 |
| AC-02 | Gate 不把迟到的旧会话响应投递给同 UID 的新连接。具有显式推送标记的消息仍投递给当前连接，不以 `seq` 或 Protobuf 解码判断投递方式。 |
| AC-03 | 默认兼容无标识的旧下行；提供严格模式，要求响应标记和会话 ID 同时存在，或明确标记为按 UID 投递的推送。逐步部署和自定义发布迁移规则见 [决策](decision.md)。 |
| AC-04 | Go 客户端按连接分配递增非零序号，按 `seq` 关联乱序响应，取消、超时和断开清理在途请求；不自动重放。示例展示有超时的请求调用。 |

本次不停止旧连接上已执行的业务，不增加跨网关踢线、全局排序、可靠投递或业务幂等。新连接通过业务协议重新拉取状态，不接收旧请求的响应。

实施状态与验证见 [进度](progress.md)。
